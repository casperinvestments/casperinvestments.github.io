# Casper Rentals

Static website for Casper Rentals, the public name of Casper Investments LLC, a rental company in Brownsville, TX. The site lists apartments in Brownsville, townhouses on Champion Dr, and small commercial suites at 4 Greenway Dr, and asks visitors to contact the company about a unit.

It is plain HTML, CSS, and a small vanilla JavaScript file. `scripts/build.py` and `scripts/update_availability.py` use the Python standard library only. `scripts/import_photos.py` also uses Pillow. The repository root is the published site. GitHub Pages for the user-site repo [casperinvestments/casperinvestments.github.io](https://github.com/casperinvestments/casperinvestments.github.io) serves the `main` branch root by default, so no Pages settings change is needed. The live site is https://casperinvestments.github.io/ . Internal links and asset paths stay relative so they work at the domain root and in local preview.

There is no custom domain, no npm build, and no paid hosting.

## Layout

The repository root is what GitHub Pages publishes.

Generated by `python3 scripts/build.py` (the build overwrites only these files):

- `index.html`, `units.html`, `working-crews.html`, `contact.html`, `404.html`
- `units/<slug>.html` (one page per unit)
- `sitemap.xml` (home, units, working crews, contact, and each unit page)
- `robots.txt`
- `.nojekyll` (empty, so Pages does not run Jekyll)

Source files, published from the root as-is (the build does not copy them):

- `assets/` — CSS, JavaScript, and images. Pages link to `assets/...` (unit pages use `../assets/...`).
- `data/availability.json` — availability the pages fetch (`data/availability.json` on top-level pages, `../data/availability.json` on a unit page).
- `data/units.json` and `site.config.json` — inputs to the build.

`scripts/` holds the build, availability, and photo-import scripts. `Archive/` keeps retired files, including the previous `docs/` output. `robots.txt` disallows `/Archive/`, and the sitemap does not list it.

Do not hand-edit the generated HTML, sitemap, or robots.txt. Edit `assets/`, `data/`, or `site.config.json`, then build again.

## Build

From the repository root:

```bash
python3 scripts/build.py
```

The script reads `site.config.json`, `data/units.json`, and `data/availability.json`, finds each unit's photos by listing `assets/img/units/<slug>/*.jpg`, and writes the generated files listed above. Re-running it is safe. It does not delete other files.

## Preview locally

From the repository root, after a build:

```bash
python3 -m http.server 8000
```

Open http://localhost:8000/

## Daily availability sync

Availability text on the site comes from `data/availability.json`. Produce the derived input outside this repository (do not commit the upstream calendar export). Each line looks like:

```text
unit_id | status | next_open_date
```

The date may be blank. Lines that start with `#` are ignored.

1. Produce the derived input text file outside the repo.
2. `python3 scripts/update_availability.py /path/to/availability-input.txt`
3. `python3 scripts/build.py`
4. Commit `data/availability.json` plus the regenerated HTML and sitemap (`index.html`, `units.html`, `working-crews.html`, `contact.html`, `404.html`, `units/*.html`, and `sitemap.xml`).

`update_availability.py` checks each id against `data/units.json`. A unit missing from the input becomes status `Contact us` with no next open date, and the script prints a warning. Unknown ids are ignored with a warning. Allowed statuses are `Available`, `Available from YYYY-MM-DD`, `Occupied`, and `Contact us`. Anything else is stored as `Contact us` with a warning. Optional `--as-of YYYY-MM-DD` sets the as-of date (the default is today). The script writes only `data/availability.json`.

The HTML is static, so the status you see is the status at build time. `assets/js/main.js` also fetches `data/availability.json` (unit pages use `../data/availability.json`) and refreshes each `data-unit-status` badge. Replacing `data/availability.json` alone updates those badges on the next page load. A full build still refreshes titles, schema, and the sitemap lastmod date.

## Photo import

Use only public Airbnb listing photos, or image files the owner sends later. Put them in a directory outside the repo, with one subfolder per unit id (`AU-A/1.jpg`, and so on). Then, from the repository root:

```bash
python3 scripts/import_photos.py /path/to/photo-source
python3 scripts/build.py
```

For each subfolder whose name is a unit id in `data/units.json`, the script takes up to five images in numeric filename order, converts them to RGB, resizes them to a width of at most 1200 pixels (no upscaling), strips metadata, and saves progressive JPEGs at quality 68 with 4:2:0 subsampling (`optimize=True`) to `assets/img/units/<slug>/01.jpg`, `02.jpg`, and so on. Unknown folders are skipped with a warning. The script does not delete files. Units with no photos keep `assets/img/placeholder.svg` (“Photos coming soon”).

## Formspree endpoint

The Formspree endpoint is set in `site.config.json` and forwards submissions to the owner's inbox configured in Formspree. Rebuild after changing that value. While `formspreeEndpoint` contains `PLACEHOLDER`, the contact page shows “The contact form is being set up. Check back soon.” and JavaScript blocks the submit so nothing is posted to the placeholder address.

`contactEmailNote` in the same file records that inquiries from the contact form are delivered to Casper Rentals through Formspree. The site does not publish an email address, phone number, or company mailing address.

The contact form can preselect a crew or group stay with `contact.html?unit=crew`. That choice is the “Crew or group stay (weekly or monthly)” option. An optional “Number of people” field and a short hint under the message ask crews for headcount, dates, and weekly or monthly.

## Working crews

`working-crews.html` is for seasonal and contract workers: Port of Brownsville LNG project crews, wind industry and wind turbine technicians, and workers near SpaceX Starbase at Boca Chica. It offers furnished weekly and monthly stays and lists only the furnished apartments and townhouses. The Greenway commercial suites (GW-SA, GW-SB, GW-SC) are not on that page and are never described as furnished. The page states that Casper Rentals is an independent local rental company and is not affiliated with any employer or project named there. Copy does not give drive times, minutes, or miles. The home page has a working-crews band, and the header, footer, units page, and sitemap link to the page.

## Canonical base URL

`baseUrl` in `site.config.json` is `https://casperinvestments.github.io` (no trailing slash). The site is served at the domain root, https://casperinvestments.github.io/ . Sitemap URLs, the robots.txt Sitemap line, canonical links, Open Graph URLs, and JSON-LD `url` and `image` values use that absolute base. A unit page canonical URL looks like `https://casperinvestments.github.io/units/aurora-a.html`. Page-to-page links and assets stay relative (`assets/...` on top-level pages, `../assets/...` and `../data/availability.json` on unit pages).
