# Casper Rentals

Static website for Casper Rentals, the public name of Casper Investments LLC, a rental company in Brownsville, TX. The site lists apartments in Brownsville and townhouses on Champion Dr, and asks visitors to contact the company about a unit. Small commercial suites at 4 Greenway Dr stay in the source data and are left off the public site while their ids are in `hiddenUnits`.

It is plain HTML, CSS, and a small vanilla JavaScript file. `scripts/build.py` and `scripts/update_availability.py` use the Python standard library only. `scripts/import_photos.py` and `scripts/optimize_images.py` also use Pillow. The repository root is the published site. GitHub Pages for the user-site repo [casperinvestments/casperinvestments.github.io](https://github.com/casperinvestments/casperinvestments.github.io) serves the `main` branch root by default, so no Pages settings change is needed. The live site is https://casperinvestments.github.io/ . Internal links and asset paths stay relative so they work at the domain root and in local preview.

There is no custom domain, no npm build, and no paid hosting.

## Layout

The repository root is what GitHub Pages publishes.

Generated by `python3 scripts/build.py` (the build overwrites only these files):

- `index.html`, `units.html`, `working-crews.html`, `contact.html`, `404.html`
- `units/<slug>.html` (one page per unit; a hidden unit is a noindex stub)
- `sitemap.xml` (home, units, working crews, contact, and each unit page; not 404)
- `robots.txt`
- `.nojekyll` (empty, so Pages does not run Jekyll)

Source files, published from the root as-is (the build does not copy them):

- `assets/` — CSS, JavaScript, images, favicons, and `assets/img/manifest.json` when it has been generated.
- `data/availability.json` — availability the pages fetch (`data/availability.json` on top-level pages, `../data/availability.json` on a unit page).
- `data/units.json` — unit ids, slugs, addresses, and the fields `scripts/update_availability.py` checks. Do not change that schema for page copy.
- `data/unit_content.json` — per-unit SEO copy keyed by unit id: `shortName`, `kind`, `about`, `highlights`, `photoRooms` (aligned with `01.jpg`, `02.jpg`, and so on), `metaDescription`, and `location`.
- `site.config.json` — site name, company, city, base URL, Formspree endpoint, `googleSiteVerification`, `googleMapsUrl`, and `hiddenUnits`.

`scripts/` holds the build, availability, photo-import, and image-optimize scripts.

`Archive/` is not part of the published repo. `robots.txt` disallows `/Archive/`, and the sitemap does not list it. `.gitignore` ignores `Archive/`. A local copy of retired files can live at `/workspace/casper-archive/`.

Do not hand-edit the generated HTML, sitemap, or robots.txt. Edit `assets/`, `data/`, or `site.config.json`, then build again.

## Build

From the repository root:

```bash
python3 scripts/build.py
```

The script reads `site.config.json`, `data/units.json`, `data/unit_content.json`, and `data/availability.json`. It reads `assets/img/manifest.json` when that file exists and uses the WebP and JPEG derivatives listed there. If the manifest is missing or a derivative is not on disk, the build uses the original JPEG in `assets/img/units/<slug>/` and does not crash. `build.py` does not import Pillow. Re-running it is safe. It does not delete other files.

## Hidden units

`hiddenUnits` in `site.config.json` is a list of unit ids to withhold from the public site. Omit the key or use `[]` to list every unit. Each id must be in `data/units.json`. Hidden units stay in `data/units.json` and `data/unit_content.json`, and they are left out of the home page, units page (cards, the “Showing N units” count, and property filter), working-crews page, “More at …” cards, contact form, sitemap, and JSON-LD. The build still writes `units/<slug>.html` for each hidden id: the site header, footer, and CSS, a heading that the unit is not currently listed, links to `units.html` and `contact.html`, and `<meta name="robots" content="noindex, nofollow">`. That stub has no canonical link, photos, or unit name. Nothing else on the site links to it. To list a unit again, remove its id from `hiddenUnits` and run `python3 scripts/build.py`. When every commercial suite id is hidden, public titles and page copy do not mention commercial suites. `scripts/update_availability.py` reads the same list and does not write those ids into `data/availability.json`.

## Daily availability sync

Availability text on the site comes from `data/availability.json`. Produce the derived input outside this repository (do not commit the upstream calendar export). Each line looks like:

```text
unit_id | status | next_open_date
```

The date may be blank. Lines that start with `#` are ignored.

1. Produce the derived input text file outside the repo.
2. `python3 scripts/update_availability.py /path/to/availability-input.txt`
3. `python3 scripts/build.py`
4. Commit `data/availability.json` plus the regenerated HTML and sitemap (`index.html`, `units.html`, `working-crews.html`, `contact.html`, `404.html`, `units/*.html`, and `sitemap.xml`).

Optimized images and `assets/img/manifest.json` only need regenerating when photos change. A daily availability sync does not need `scripts/optimize_images.py`.

`update_availability.py` checks each id against `data/units.json`. A unit missing from the input becomes status `Contact us` with no next open date, and the script prints a warning. Unknown ids are ignored with a warning. Ids in `hiddenUnits` are not written, are not warned as missing, and are ignored if they appear in the input. Allowed statuses are `Available`, `Available from YYYY-MM-DD`, `Occupied`, and `Contact us`. Anything else is stored as `Contact us` with a warning. Optional `--as-of YYYY-MM-DD` sets the as-of date (the default is today). The script writes only `data/availability.json`.

The HTML is static, so the status you see is the status at build time. `assets/js/main.js` also fetches `data/availability.json` (unit pages use `../data/availability.json`) and refreshes each `data-unit-status` badge and `data-unit-next-open` line. Replacing `data/availability.json` alone updates those badges on the next page load. A full build still refreshes titles, schema, and the sitemap lastmod date. The sitemap `lastmod` is the availability `asOf` date, or the build date when `asOf` is blank.

## Photo import

Use only public Airbnb listing photos, or image files the owner sends later. Put them in a directory outside the repo, with one subfolder per unit id (`AU-A/1.jpg`, and so on). Then, from the repository root:

```bash
python3 scripts/import_photos.py /path/to/photo-source
python3 scripts/optimize_images.py
python3 scripts/build.py
```

For each subfolder whose name is a unit id in `data/units.json`, the import script takes up to five images in numeric filename order, converts them to RGB, resizes them to a width of at most 1200 pixels (no upscaling), strips metadata, and saves progressive JPEGs at quality 68 with 4:2:0 subsampling (`optimize=True`) to `assets/img/units/<slug>/01.jpg`, `02.jpg`, and so on. Unknown folders are skipped with a warning. The script does not delete files. Units with no photos keep `assets/img/placeholder.svg` (“Photos coming soon”). After a successful import it prints a reminder to run `scripts/optimize_images.py`.

`scripts/optimize_images.py` is idempotent. For each source JPEG it writes `assets/img/units/<slug>/opt/NN-400.webp`, `NN-400.jpg`, `NN-800.webp`, `NN-800.jpg`, `NN-1200.webp`, and `NN-1200.jpg`. It keeps the aspect ratio, never upscales, and caps the large size at 1600 pixels when a source is wider than that. WebP uses quality 72 and method 6. JPEGs are progressive, quality 72, with metadata stripped. A derivative newer than its source is left alone. Source JPEGs are never overwritten or deleted. The script also writes `assets/img/manifest.json` and draws `assets/img/favicon-32.png` (32×32) and `assets/img/apple-touch-icon.png` (180×180). The SVG mark is `assets/img/favicon.svg`.

The build renders each photo as a `<picture>` with WebP and JPEG `srcset` values when the manifest entry is usable. Thumbnail links point at the 1200 JPEG derivative. `assets/js/main.js` swaps the unit-page main photo, including the `<source>` and `<img>` `srcset` values, width, height, and alt text.

## Favicons and theme color

Every page links `assets/img/favicon.svg`, `assets/img/favicon-32.png`, and `assets/img/apple-touch-icon.png`, and sets `<meta name="theme-color" content="#0b4f5c">`. Unit pages prefix those paths with `../`.

## Search Console

`googleSiteVerification` in `site.config.json` starts as an empty string. On `index.html` only, an empty value becomes an HTML comment telling you to set the key and rebuild. A non-empty string becomes `<meta name="google-site-verification" content="...">`. The build does not contact Google or any other service.

## Titles, social tags, and JSON-LD

Each generated page has its own `<title>` and meta description. `og:title`, `og:description`, `twitter:title`, and `twitter:description` repeat that pair. Every page also has a canonical URL, `og:site_name`, `og:type` (`website`), `og:url`, `og:image`, `og:image:alt`, `og:locale` (`en_US`), `twitter:card` (`summary_large_image`), `twitter:image`, and `twitter:image:alt`. Open Graph and Twitter images are absolute URLs of a real unit JPEG. Unit pages use that unit's `01.jpg`. Pages without a photo, including the commercial suites, use a real photo such as `assets/img/units/aurora-a/01.jpg` rather than the placeholder SVG. `404.html` adds `<meta name="robots" content="noindex">` and is omitted from the sitemap.

JSON-LD is one object per `<script type="application/ld+json">` block. The home page uses `LodgingBusiness` and `LocalBusiness` (with `@id` `https://casperinvestments.github.io/#business`). It has no `streetAddress`, telephone, email, or `priceRange`. The contact point is the contact page URL. Unit pages use `Apartment` for Greenway apartments and Aurora, `House` for Champion Dr townhouses, and `Accommodation` for the Greenway commercial suites, plus a `BreadcrumbList` (Home, Units, unit). Names in those blocks use the short name from `data/unit_content.json`. The units page and the working-crews page keep an `ItemList`. Working crews also keeps a `WebPage` block. No JSON-LD on the site includes `streetAddress`.

`robots.txt` is:

```text
User-agent: *
Allow: /
Disallow: /Archive/

Sitemap: https://casperinvestments.github.io/sitemap.xml
```

## Formspree endpoint

The Formspree endpoint is set in `site.config.json` and forwards submissions to the owner's inbox configured in Formspree. Rebuild after changing that value. While `formspreeEndpoint` contains `PLACEHOLDER`, the contact page shows “The contact form is being set up. Check back soon.” and JavaScript blocks the submit so nothing is posted to the placeholder address.

`contactEmailNote` in the same file records that inquiries from the contact form are delivered to Casper Rentals through Formspree. The site does not publish an email address, phone number, or company mailing address. Visible copy and JSON-LD point people to https://casperinvestments.github.io/contact.html .

The contact form can preselect a crew or group stay with `contact.html?unit=crew`. That choice is the “Crew or group stay (weekly or monthly)” option. A unit page links to `contact.html?unit=<ID>`. An optional “Number of people” field and a short hint under the message ask crews for headcount, dates, and weekly or monthly.

## Working crews

`working-crews.html` is for seasonal and contract workers: Port of Brownsville LNG project crews, wind industry and wind turbine technicians, and workers near SpaceX Starbase at Boca Chica. It offers furnished weekly and monthly stays and lists only the furnished apartments and townhouses. The Greenway commercial suites (GW-SA, GW-SB, GW-SC) are not on that page and are never described as furnished. Any page that names Starbase, LNG, or wind projects includes this footnote: “Casper Rentals is an independent local rental company and is not affiliated with any employer or project named on this page.” Copy does not give drive times, minutes, or miles. The home page has a working-crews band, and the header, footer, units page, and sitemap link to the page.

## Canonical base URL

`baseUrl` in `site.config.json` is `https://casperinvestments.github.io` (no trailing slash). The site is served at the domain root, https://casperinvestments.github.io/ . Sitemap URLs, the robots.txt Sitemap line, canonical links, Open Graph URLs, Twitter image URLs, and JSON-LD `url` and `image` values use that absolute base. A unit page canonical URL looks like `https://casperinvestments.github.io/units/aurora-a.html`. Page-to-page links and assets stay relative (`assets/...` on top-level pages, `../assets/...` and `../data/availability.json` on unit pages).

## Rent

Every unit shows rent as “Contact us”. The unit page availability section says “Rent: Contact us for pricing”. Do not add prices or other money amounts to the site.
